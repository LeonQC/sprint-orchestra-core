# --- Distributed tracing (app/tracing.py), optional: VEC_TRACING_ENABLED=true ---
# This service is the downstream half of a two-service request. It already timed its own stages
# (embed / retrieval / rerank) into Prometheus and a structured log, but those numbers could not be
# read alongside the caller's — an `x-request-id` correlates log lines and carries no parent/child
# relationship or durations. FastAPI instrumentation extracts the W3C `traceparent` ai-service now
# injects, so these stages become children of the /ask span that caused them.
#
# The instrumentation packages version on their own line (0.65b0) rather than tracking the SDK
# (1.44.0); mixing the two lines fails at import, not at resolve time. Kept byte-identical to
# ai-service's pins so both services export to one collector with one wire format.
opentelemetry-sdk==1.44.0
opentelemetry-exporter-otlp-proto-grpc==1.44.0
opentelemetry-instrumentation-fastapi==0.65b0
# httpx client instrumentation: this service calls the litellm gateway over httpx now, so it needs
# to inject `traceparent` (join the caller's trace) the same way ai-service does.
opentelemetry-instrumentation-httpx==0.65b0
# Semantic-convention constants only (SpanAttributes, OpenInferenceSpanKindValues) — not an
# instrumentor, this service has no LLM SDK of its own to patch. Labels the embed/retrieval/rerank
# stage spans above with the OpenInference span kind (EMBEDDING/RETRIEVER/RERANKER) they actually
# are, so Phoenix and Langfuse show what each stage IS instead of a kind-less generic span. Pinned
# to the exact version ai-service already runs, for the same one-wire-format reason as the pins above.
openinference-semantic-conventions==0.1.30
